PukuCloud has three main layers:

1. **Control plane** — API, auth, organizations, tokens, templates, databases, and orchestration.
2. **Data plane** — agents that run sandbox operations on hosts.
3. **Workload microVMs** — Firecracker sandboxes created from templates.

## Public surfaces

On a self-hosted deployment these are whatever hostnames you choose; the hosted
service uses:

- Dashboard: `app.pukucloud.ai`
- API: `api.pukucloud.ai`
- Docs: `docs.pukucloud.ai`

## API entry points

```http
GET /healthz
GET /version
GET /metrics
GET /v1/me
POST /v1/sandboxes
GET /v1/templates
POST /v1/databases
```

Sandbox operations are scoped under `/v1/sandboxes/{id}`. Filesystem access uses `/fs`, lifecycle uses routes such as `/pause`, `/resume`, `/snapshots`, `/fork`, `/hibernate`, and `/wake`, and streaming uses `/exec/stream`, `/events`, and WebSocket upgrades.

## Agent-proxied operations

```http
POST /v1/sandboxes/{id}/exec
POST /v1/sandboxes/{id}/exec/stream
GET /v1/sandboxes/{id}/exec/pty
GET /v1/sandboxes/{id}/exec/ws
GET /v1/sandboxes/{id}/logs
GET /v1/sandboxes/{id}/events
GET /v1/sandboxes/{id}/lsp/{lang}
```

## Client configuration

```bash
export PUKUCLOUD_API_KEY=pds_abc123def456...
export PUKUCLOUD_API=https://api.pukucloud.ai
```

The Python SDK imports from `pukucloud`; the TypeScript SDK imports from `@pukucloud/sdk`; the CLI binary is `pukucloud`.

## Lifecycle model

Use `Sandbox.create(...)` or `pukucloud sandbox create` to start a sandbox, `exec` or `run_code` to run work, `sandbox.filesystem` or `sandbox cp` for files, and `kill` or `pukucloud sandbox delete` to clean up. Advanced lifecycle operations include pause, resume, snapshot, fork, hibernate, wake, TTL changes, and persistence changes.
